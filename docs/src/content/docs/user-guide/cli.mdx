title: HAEVN CLI
description: Use HAEVN from your terminal for search, branch navigation, imports, and exports.

The HAEVN CLI (`haevn`) gives you fast terminal access to your local archive.

Use it when you want to:
- search quickly across large archives,
- inspect branch topology,
- fetch one exact thread for writing/research,
- script workflows with JSON output.

## Setup

1. Install the CLI:

```bash
npm install --global @haevn/cli
# or: pnpm add --global @haevn/cli
```

2. Open HAEVN extension **Settings** and copy your CLI API key.
3. Start the daemon:

```bash
haevn daemon --api-key <your-key>
```

4. In another terminal, run commands:

```bash
haevn list -l 5
```

## Commands at a glance

- `haevn list` — browse chats (`msgs` and `br` columns included).
- `haevn search "<query>"` — message-level search with context snippets.
- `haevn branches <chatId>` — inspect tree/forks with short message refs.
- `haevn get <chatId> -m <messageRef>` — fetch one branch by short ref.
- `haevn info <chatId>` — view or edit metadata for a single chat.
- `haevn export <chatId> -o file --format <haevn_json|haevn_markdown|pi_session_jsonl>` — export one chat.
- `haevn import --format <claude_code|codex|pi|openrouter> <file...>` — import local JSONL session files or an OpenRouter chatroom export.
- `haevn health` — check that each web provider you are signed in to still syncs (read-only).
- `haevn logs` — read the extension's recent log entries (`--level`, `--context`, `--match`).

## Short message refs

CLI output shows short refs like `80a6c24e0af9`.

- Pass them directly to `haevn get -m`.
- Use `haevn branches --show-ids` if you also need raw IDs.

### Search syntax

The CLI supports the same advanced search syntax as the UI:

**Basic (AND):**
```bash
haevn search "python async function"
```

**Exact phrases:**
```bash
haevn search '"machine learning"'
```

**Exclude terms:**
```bash
haevn search "react hooks -class"
```

**Fuzzy matching:**
```bash
haevn search "kubernates~2"
```

**Prefix/wildcard:**
```bash
haevn search "async*"
```

| Operator | Example | Description |
|----------|---------|-------------|
| `+` | `+required` | Must be present (default behavior) |
| `-` | `-exclude` | Must NOT be present |
| `*` | `react*` | Prefix/wildcard match |
| `~` | `roam~2` | Fuzzy match (edit distance) |
| `^` | `term^10` | Accepted and ignored (no term has more weight than another) |
| `"..."` | `"exact phrase"` | Phrase must appear consecutively |

## Viewing and editing chat metadata

The `info` command lets you inspect or update the [AI-generated metadata](/user-guide/metadata/) for any chat.

```bash
# View current metadata (title, description, synopsis, categories, keywords)
haevn info <chatId>

# Set or override individual fields
haevn info <chatId> --title "Better Title"
haevn info <chatId> --description "A short summary"
haevn info <chatId> --categories "Coding,DevTools Automation"
haevn info <chatId> --keywords "typescript,chrome-extension"

# Trigger AI generation (or re-generation) for one chat
haevn info <chatId> --generate

# Output as JSON
haevn info <chatId> --format json
```

Sample output:

```text
━━ metadata  68937df7-e198-8325-973e-ed9528104e0c

  Title:         Emergence and Consciousness Research
  Description:   Explores philosophical frameworks for emergent intelligence and AI consciousness.
  Synopsis:      The user asks for research on philosophical approaches to consciousness …
  Categories:    AI Research, Philosophy and Consciousness
  Keywords:      emergence, consciousness, rlhf, post-human

  source: ai  updated 2 hours ago · generated 2 hours ago
```

## Exporting from CLI

CLI exports route through the extension's exporter pipeline (same source of truth as UI exporters).

```bash
# Canonical JSON (default)
haevn export <chatId> -o chat.json --format haevn_json

# Markdown transcript
haevn export <chatId> -o chat.md --format haevn_markdown

# Pi session JSONL
haevn export <chatId> -o chat.jsonl --format pi_session_jsonl
```

Current CLI export constraints:
- single chat per command
- no media payload transfer (`includeMedia=false` on daemon bridge)

This keeps daemon requests small and avoids long-running payload transfers from the extension.

## JSON mode for automation

Use `--format json` and pipe to `jq`:

```bash
haevn search "emergence" --format json | jq '.results[0] | {chatId, messageRef, source}'
```

Useful fields:
- `search`: `chatId`, `messageRef`, `messageSnippet`, `source`
- `branches`: `tree`, `branches[].leafMessageRef`, `branches[].path`
- `get`: branch content suitable for markdown or structured JSON workflows

## Import from local session files

You can import local coding-session artifacts directly from the terminal:

```bash
# Claude Code session JSONL
haevn import --format claude_code ~/.claude/projects/my-proj/session.jsonl

# Codex session JSONL
haevn import --format codex ~/.codex/sessions/2026/03/23/rollout-...jsonl

# PI session JSONL
haevn import --format pi ~/.pi/sessions/2026-03-23T14-48-43-844Z_...jsonl

# OpenRouter chatroom export (one file, one chat per chatroom)
haevn import --format openrouter ./open-router-chats.json
```

Flags:
- `--no-overwrite` — skip chats that already exist (default is overwrite).
- `--skip-index` — skip index rebuild after import (default is rebuild at end).

## Check that your providers still work

A site can change under HAEVN without any HAEVN release. `haevn health` asks the extension, in your own Chrome, to try each web provider you are signed in to: it opens a tab on the provider's site, lists your chats, fetches the first two, converts them the way a sync does, and checks the result (messages present, turns in order, no empty text, sane dates, a tree that leads to the current message).

```bash
haevn health                       # every web provider
haevn health -p claude,chatgpt     # only these
haevn health -n 3                  # three chats each (default 2, at most 5)
haevn health -f json               # the report as JSON
```

```text
  provider   status         signed in  listed  checked  time
  claude     ok             yes        120     2        1.4 s
  gemini     fail           yes        86      2        19.2 s
  grok       not signed in  no         -       -        0.5 s

  gemini     fail  text.empty x3 in 2 of 2 chats: a text, thinking or prompt part is an empty string
```

- **Your archive is never changed.** No chat is saved, no media is stored, nothing is indexed, and a chat already in your archive is never overwritten by what the check fetched. Two things still happen, as when you browse the site: for ChatGPT, the check loads the images of the chats it fetches into memory and discards them; and loading a provider's tab can refresh the sign-in details HAEVN already keeps for that site.
- **The report holds no chat text, titles or ids**, only counts, the names of the rules that failed and short reasons, so you can paste it into a bug report. (The extension's own log, `haevnDebug.getLogs()`, can mention a chat as it does in a sync.)
- **Not signed in** and **unreachable** are rows, not failures, and the provider was *not checked*; the last line says how many were. A provider you know you are signed in to that shows `not signed in` is a failure of the check or of the sign-in details HAEVN keeps for it, not a pass: read its note.
- It opens real tabs (Gemini and AI Studio in the foreground, as a bulk sync does) and takes from a few seconds to a few minutes. It will not start while a sync, import or export is running.
- **Time.** Each provider gets 40 s, and Gemini and AI Studio 120 s, since they open each chat's page to read it; the whole run gets 4 minutes. Claude, ChatGPT and Gemini are checked first, then the rest, so a slow run skips the others and never these. A large account can spend its limit listing its chats (the row says `TIMEOUT` and `listing the chats`): run that provider alone with a longer limit, `haevn health -p chatgpt --timeout 120`.
- Open WebUI is checked only when its address is set in the settings.
- **Exit code:** 1 when a provider failed or timed out, or when Claude, ChatGPT or Gemini was skipped because the run ran out of time; 0 otherwise. The same check is `haevnDebug.providerHealth()` in the browser console of the Options page.

### What a finding means

A `fail` is a rule that makes a chat unusable (no messages, a current message that is not in the tree, an empty text, a date outside 2015 to tomorrow). A `warn` is odd but possible and never changes the exit code. Some are expected on a healthy account:

- `title.fallback` on the newest chat: the head of the list is where untitled chats are.
- `tree.multiple-roots` on Poe: a chat break starts a new root by design.
- `text.empty` on ChatGPT is most likely a finding about HAEVN's converter (it may read the text of a reasoning node from the wrong place), not about the site. Report it; do not treat it as the site being down.
- `roles.not-alternating` counts only two of your own messages in a row (a reply that was dropped). A model that answers in several steps, as ChatGPT does, is not one.

## Read the extension's log

`haevn logs` reads the extension's recent log entries from the terminal, so a sync or a health run can be checked without copying the console by hand:

```bash
haevn logs -n 200 --level warn                 # the newest warnings
haevn logs --context background --match sync   # the service worker's entries that mention sync
haevn logs -f json                             # the entries whole, with their data
```

`--level` keeps exactly one level, so `warn` leaves out the errors. `--match` is a case-insensitive substring. Log entries name a chat by its id and a provider by its name, but some carry text too (a chat title, a search query, a part of a reply), so read them before you share them.

## Tips

- Increase snippet context for dense technical/philosophical text: `-c 220`.
- Use `list --sort messageCount` to surface large or branch-heavy chats first.
- Keep `get` without media unless needed for payload speed and readability.
- Use `get --include-thinking` when you need full reasoning blocks instead of previews.
- Use `get --skip-system` to hide system instructions from output.
