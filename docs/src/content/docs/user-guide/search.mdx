HAEVN indexes the full text of every synced conversation, so you can search across your entire archive in milliseconds — regardless of which platform a conversation came from.

## How to search

Type in the **search box** at the top of the Archive view. Results appear automatically as you type, grouped by conversation and showing matching snippets.

<Image src={searchImg} alt="Search results for 'poem' showing matching conversations from multiple platforms, with highlighted snippets from the matching messages" />

Each result shows:
- The **conversation title** and source platform
- **Matching message snippets** with the search term highlighted in context
- A **Show more** button if there are many matching messages within a conversation
- **Open in Viewer** and **Export** buttons to act on results directly

<Aside type="tip">
  Click **Open in Viewer** directly from a search result — the viewer will scroll to the matching message and highlight the search term in context.
</Aside>

## Search syntax

HAEVN searches with **SQLite full-text search** (FTS5) and supports advanced query operators.

### Basic queries

**Multiple terms (AND):** By default, all terms must match (AND logic).
```
python async function
```
This finds messages containing all three terms: `python` AND `async` AND `function`.

**Exact phrases:** Wrap your query in double quotes to match a specific phrase in order.
```
"Ingeborg Bachmann"
```
The words must appear consecutively and in that exact order.

### Advanced operators

| Operator | Example | Description |
|----------|---------|-------------|
| `+` | `+required` | Term **must** be present (AND). Default behavior. |
| `-` | `-exclude` | Term must **not** be present (NOT). |
| `*` | `react*` | Prefix/wildcard — matches `react`, `reactive`, `reactor`, etc. |
| `~` | `roam~2` | Fuzzy match with edit distance 1 or 2 — catches typos like `room`, `foam`. |
| `^` | `important^10` | Accepted and ignored: no term weighs more than another. |
| `"` | `"exact phrase"` | Phrase search — terms must appear consecutively. |
| `model:` | `model:gpt-4o` | The chat has a model with these words. `model:sonnet` finds `claude-3-5-sonnet`. The words must be next to each other: `model:gpt-4` finds `gpt-4` but not `gpt-4o`; `model:gpt-4*` finds both. |
| `tag:` | `tag:poetry`, `tag:"creative writing"` | The chat has a tag with these words. `-tag:draft` leaves out the chats that have it. |

### Models and tags

Every chat is indexed with the models it used and the tags it carries, whether it was synced from a platform or imported from a file. A plain word, and `-word`, are about what was said: they never look at the models and tags, so `poetry` finds the chats that mention poetry and not the ones that are only tagged `poetry`, and `python -claude` does not drop the chats whose model is called `Claude`. Only `model:` and `tag:` look at the models and the tags (`tag:poetry` finds the tagged chats), and `-model:` and `-tag:` leave chats out by them. A chat keeps its first 50 models and first 50 tags in the index; a later one is not found. A result that is a model or a tag says so, instead of "User" or "Assistant", and opens the chat at the top.

<Aside type="note">
  After an update that changes the index, HAEVN rebuilds it by itself the next time the extension starts. Until it has finished, a search says that the index is rebuilding instead of returning an empty list. The updates that added `model:` and `tag:`, and that made it find ChatGPT chats by the model of each reply, are two of these. Chats from ChatGPT and Grok are found by their models as soon as the index is rebuilt; a Claude chat is found by its model after it is synced again. Chats synced from some other platforms (for example Gemini and DeepSeek) still carry the platform's own name as their model, not the model of each reply.
</Aside>

### Examples

**Exclude unwanted results:**
```
react hooks -class
```
Finds messages about React hooks but excludes any mentioning "class".

**Fuzzy matching for typos:**
```
kubernates~2
```
Matches "kubernetes" even with the typo.

**Prefix search:**
```
async* await*
```
Matches "async", "asynchronous", "await", "awaiting", etc.

### Automatic fallback

If your strict AND query returns no results, HAEVN automatically retries with relaxed prefix matching (OR semantics). This helps when exact terms don't match but similar terms exist.

### Tips

- **Titles are boosted:** Conversation titles have 10x relevance weight, so short queries often surface the right conversation first.
- **Case-insensitive:** Search ignores case, and the accents of Latin letters: `cafe` finds `café`.
- **Stop words are skipped in a query:** common words like "the", "a" and "is" do not narrow a search that has other words in it; inside a "quoted phrase" they count.

## How search works

HAEVN builds a full-text index of your conversations in a SQLite database in your browser's private file storage. The index is updated as conversations are synced — new conversations become searchable immediately after syncing. A rebuild writes a new file and swaps it in, so search keeps answering while it runs.

Key characteristics:
- The index runs entirely **in your browser** — no search queries leave your machine
- The index is stored locally and persists across browser sessions
- Search runs in a Web Worker to avoid blocking the UI

<Aside>
  If search shows no results when you expect some, the index may need to be rebuilt. Open the browser console on the Options page and run `haevnDebug.rebuildIndex()`. See [Troubleshooting](/reference/troubleshooting/) for more.
</Aside>

## Filtering search results

After searching, use the **Provider** dropdown to filter results to a specific platform. This is useful when you know the conversation was on ChatGPT vs Claude, for example.
